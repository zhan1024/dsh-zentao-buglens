# 禅图 BugLens 使用说明

适用版本：`dsh-zentao-buglens@0.1.0`。独立 Skill 名称：`zentao-buglens`。

面向测试同事、开发同事和团队管理员。本文按已发布版本的实际功能编写。

通过 AI 工具调用独立 Skill 的同事，可直接阅读 [Skill 专用使用说明](./SKILL-USER-GUIDE.zh-CN.md)，其中包含安装、截图导入和可复制的调用话术。

## 1. 工具能做什么

禅图 BugLens 将「截图或红框标注＋一句问题描述」整理成规范 Bug 材料，再按你选择的负责人提交禅道。

日常流程：**截图 → 简述现象 → AI 分析 → 选择推荐答案 → 确认分工和负责人 → 创建禅道 Bug**。

- 支持多张截图、红框圈选、图片说明和排序。
- 通过推荐选项澄清预期、复现步骤和业务操作路径，允许自己填写答案。
- 给出前端、后端、前后端共同或待定位的排查建议，并列出依据。
- 从可核验的本人指派记录中推荐近期同事，也支持搜索团队成员。
- 创建禅道 Bug，上传截图及故障材料，回读编号、负责人和上传结果。
- 可只下载故障材料，不创建禅道 Bug。

DSH 插件和 Skill 是两个独立入口，共用本机核心服务与工作台。安装 Skill 不要求先安装 DSH。浏览器扩展是可选取证组件，用来结合已登录的业务页面采集上下文。

## 2. 安装与启动

### 2.1 环境要求

独立工作台和 CLI 要求 Node.js **22.15 或以上**。DSH 还需满足其自身的运行环境要求；本项目已测试的 DSH `0.2.2-rc.1` 要求 Node.js 24.9 或以上、pnpm 10 或以上。

可先检查本机环境：

```sh
node --version
npm --version
```

### 2.2 安装独立 Skill

在终端运行：

```sh
npx --yes dsh-zentao-buglens@0.1.0 install-skill
```

默认安装位置：

```text
~/.agents/skills/zentao-buglens
```

安装器的 `--target` 指定 skills 的父目录，安装器会在其下创建 `zentao-buglens` 文件夹。例如：

```sh
npx --yes dsh-zentao-buglens@0.1.0 install-skill --target /absolute/path/to/skills
```

已有同名目录时安装器会停止，保留已有文件。先备份个人修改，再决定是否替换。也可从 [GitHub Release](https://github.com/zhan1024/dsh-zentao-buglens/releases/tag/v0.1.0) 下载独立 Skill ZIP，将其中的 `zentao-buglens` 目录放入宿主的 skills 目录。

在已识别此 Skill 的工具中输入：

```text
$zentao-buglens
请帮我整理截图中的故障。先打开工作台，让我粘贴截图、描述问题，
再通过推荐选项补全材料。这次先整理材料，不提交禅道。
```

Skill 不会自动获得聊天截图文件或浏览器权限。如果宿主无法把聊天图片作为文件传入，直接在本机工作台粘贴图片。

### 2.3 安装 DSH 插件

已有 DSH 的用户可运行：

```sh
dsh plugin --profile web add dsh-zentao-buglens@0.1.0
dsh web
```

在 DSH 中输入：

```text
打开禅图 BugLens，我要根据截图整理故障材料。
先让我确认预期结果、职责建议和负责人，再提交禅道。
```

### 2.4 直接打开工作台

不通过 Skill 或 DSH，也可以直接运行：

```sh
npx --yes dsh-zentao-buglens@0.1.0 open
```

经常使用或需要加载浏览器扩展时，推荐全局安装，保证 CLI 和扩展目录稳定：

```sh
npm install -g dsh-zentao-buglens@0.1.0
dsh-zentao-buglens open
```

命令会启动或复用本机工作台并尝试打开浏览器；若未自动打开，请使用终端返回的完整地址。地址中含 `#token=`，仅用于本机访问，不要转发或公开。

## 3. 首次配置：由管理员完成

安装成功不代表已接入团队模型和禅道。AI 分析需要识图模型配置，提单需要测试同事自己的禅道身份及权限。

### 3.1 配置模型网关

在仓库外保存私有配置文件，例如 `~/.config/zentao-buglens/config.local.json`。下面是结构示例，网关和模型名称必须替换为团队实际值：

```json
{
  "ai": {
    "baseUrl": "https://your-team-ai-gateway.example/v1",
    "model": "your-vision-model",
    "apiKeyEnv": "BUGLENS_AI_KEY"
  },
  "zentao": {
    "profile": ""
  },
  "defaults": {
    "openedBuild": ["trunk"]
  }
}
```

模型必须支持 Chat Completions 兼容接口、`image_url` 图片输入和 JSON 对象输出。远程服务使用 HTTPS。`baseUrl` 是 API 根地址，不要重复填写 `/chat/completions`。

管理员通过操作系统环境或凭据注入工具设置 `BUGLENS_AI_KEY`。配置文件只记录环境变量名称，不填写真实 Key，也不要将 Key 发到聊天或放入报告。

在启动工作台的同一环境中指定配置文件：

```sh
# macOS / Linux：先确保文件已创建，且模型 Key 已安全注入。
export BUGLENS_CONFIG="$HOME/.config/zentao-buglens/config.local.json"
dsh-zentao-buglens open
```

Windows PowerShell 示例：

```powershell
$env:BUGLENS_CONFIG = 'C:\Users\you\.config\zentao-buglens\config.local.json'
dsh-zentao-buglens open
```

DSH 入口也要从能够读取相同配置和环境变量的环境启动。若工作台服务已经运行，更新配置后需由管理员重启该服务；重复运行 `open` 可能复用旧进程，不会自动重新加载配置。

### 3.2 登录个人禅道

在测试同事自己的交互终端运行：

```sh
npm install -g zentao-cli
zentao login
```

按 CLI 提示完成本人登录，不要将密码或 Token 发送给 AI。插件优先复用本机登录 Profile；多账号场景可由管理员在 `zentao.profile` 指定已有 Profile。

当前适配基于禅道 API v2 与 SDK 的版本检查，基线为开源 22.0 / 企业 biz13.0 / 旗舰 max8.0 / IPD ipd5.0。私有部署的权限、自定义必填字段、操作历史、附件及富文本过滤规则需要团队做实际验收。具体配置见 [团队配置与禅道接入](./CONFIGURATION.md)。

### 3.3 检查连接

打开工作台，点击右上角 **「检查连接」**，查看模型是否已配置、禅道是否已连接本人账号。模型显示已配置只代表配置存在，仍需实际分析一张允许使用的截图验证模型调用。

正式使用前，管理员应验证产品和团队列表能读取，并在授权的测试产品完成一次提单及附件验收。产品 ID、项目 ID 和版本必须使用真实值；不要直接使用配置模板中的产品 `0`。

## 4. 测试同事日常操作

### 第一步：新建材料，粘贴截图

1. 点击 **「＋ 新建故障材料」**。
2. 使用 `Ctrl+V` / `Command+V` 粘贴截图；也可以拖入图片或点击 **「＋ 添加截图」**。
3. 点击图片缩略图，在图上拖动鼠标框出问题区域。
4. 填写 **「这张图说明了什么」**，点击 **「保存圈选与说明」**。
5. 在 **「简单描述问题」** 中写一句现场现象。

例如：

> 客户管理页新增客户后点击保存，页面提示成功，但刷新列表后找不到刚新增的客户。

支持 PNG、JPEG、WebP，最多 **8 张**，每张不超过 **10MB**。多张截图可以分别填写说明，并用 **「向前移动」** 调整顺序。每张图最多保存 8 个圈选区域；当前分析会额外放大处理每张图的前 3 个选区。

外部工具已经画过红框的图片也可使用，但属于模型辅助识别；在工作台画框会保存准确坐标。浏览器扩展截取当前可视区域，不会自动生成整页长截图。

### 第二步：补充页面信息

仅粘贴图片时，可在 **「截图对应的页面地址（可选）」** 中填写真实地址，业务菜单路径也可以写入问题描述。

需要结合当前浏览器页面、操作记录和请求时，按第 5 节安装配套扩展。仅凭一张截图，工具不能自动读取网页背后的接口、源码或服务器日志。

### 第三步：分析并回答推荐问题

点击 **「分析截图，生成材料」**。工具会根据截图、选区、描述和已采集的页面信息生成材料。

需要澄清时会显示 **「再确认几个细节」**，例如：

- 保存后应该立即出现在列表，还是需要等待审核？
- 问题是否能稳定复现？
- 具体发生在哪个菜单和页面？

这些是使用场景示例，实际问题和选项由模型根据证据生成，可能不提问。选择符合现场的答案，也可自己填写，点击 **「应用到故障材料」**。

随后核对标题、业务操作路径、复现步骤、实际结果和预期结果。对 AI 推测的预期，应通过推荐问题填写确认答案，或在 **「预期结果」** 中修改成准确表述；材料会区分测试同事填写/确认与 AI 推测的来源。

### 第四步：确认排查职责

在 **「职责建议」** 中选择：

| 选项 | 使用方式 |
| --- | --- |
| 前端 | 有证据支持优先检查页面状态、交互、展示或请求构造。 |
| 后端 | 有证据支持优先检查接口校验、业务处理或数据落库。 |
| 前后端共同 | 需要双方核对协议、请求、响应及页面处理，并分别列出事项。 |
| 待定位 | 当前证据不足，保留待核实问题，先安排排查。 |

同时检查 **「判断依据」「前端事项」「后端事项」「待补充信息」**。职责是排查建议，不是根因裁定；不能仅凭 HTTP 500 或页面提示成功就判定责任。

### 第五步：选择产品、版本和开发同事

1. 选择真实的 **「所属产品」**，按需选择 **「所属项目」**。
2. 填写 **「影响版本」**：`trunk` 或实际版本 ID，多个值用逗号分隔。
3. 点击 **「↻ 同步禅道历史」**。
4. 在 **「最近指派过的同事」** 中选择人员，或通过 **「搜索负责人」** 查找姓名/账号。
5. 确认 **「主负责人」**，按需选择协作人。

最近指派来自当前禅道身份可核验的本人操作历史及本工具成功指派记录。默认扫描当前产品最近编号的最多 200 个可访问 Bug，查找最近 30 天的本人指派事件；界面会说明扫描范围，不代表全量历史。站点不开放历史或姓名无法唯一对应账号时，仍可手动选择可访问的团队成员。

共同问题创建 **一条 Bug、一个主负责人**；协作人和分工写入正文，不会自动拆成两条 Bug，也不保证禅道发出协作通知。

### 第六步：提交或只下载材料

只需要材料时，点击 **「下载故障材料」**：

- 浏览器下载包含图片和红框的离线 HTML，可直接交给同事阅读。
- Markdown 和 HTML 同时保存在本机数据目录的 `exports` 中。
- 单独分享 Markdown 时需另带对应图片；它不像 HTML 一样内嵌全部图片。
- 导出不会创建禅道 Bug。

需要提单时，核对材料、严重程度、优先级、产品、影响版本和主负责人，再点击 **「创建禅道 Bug →」**。该按钮会执行真实写入。

成功后应看到真实 Bug 编号、**「打开禅道 Bug ↗」** 链接和完成状态。工具会上传原图、工具内圈选的标注图、Markdown 与 HTML 材料，并检查正文嵌图及附件关联。打开禅道详情复核负责人、材料与图片。

开始提交后该草稿会冻结，以保证上传内容一致。若需修订，先核实原 Bug 状态，再按团队流程处理；不要因报错就新建相同草稿重复提单。

## 5. 可选：浏览器截图与接口取证

### 5.1 安装扩展并配对

1. 全局安装并运行 `dsh-zentao-buglens open`。
2. 运行 `dsh-zentao-buglens extension-path`，记下返回的扩展目录。也可从 Release 下载扩展 ZIP，解压到固定目录。
3. 打开 `chrome://extensions` 或 `edge://extensions`，启用开发者模式，选择 **「加载已解压的扩展程序」**，选择扩展目录。
4. 打开扩展，将当前工作台完整地址粘贴到 **「完整工作台地址」**，点击 **「保存本机配对」**。
5. 回到已登录的普通业务页面，在扩展内填写简单描述，点击 **「截图并打开提单工作台 ↗」**。

扩展将截图和当前页面信息放进新草稿，再打开工作台。配对必须使用含 `#token=` 的完整 `http://127.0.0.1:端口/` 地址。工作台服务重启后使用新地址重新配对。

当前扩展通过 ZIP/开发者模式分发，未上架 Chrome Web Store 或 Edge Add-ons。浏览器设置页、扩展商店等受限页面不支持取证。

### 5.2 收集复现过程

1. 在故障发生前打开扩展。
2. 如确有需要，先勾选 **「同时采集接口入参与 JSON 响应」**，再点击 **「开始取证」**。
3. 回到当前业务页签，执行复现操作。
4. 问题出现后点击 **「停止取证」**，再填写描述并截图。已采集记录会随下次截图带入。

| 材料 | 当前版本的采集方式与边界 |
| --- | --- |
| 页面路由/地址 | 扩展读取采集当时的真实 URL。 |
| 菜单、模块、按钮路径 | 结合可见面包屑、标题、控件和截图生成建议，需测试核对补全。 |
| 点击、导航、控制台报错 | 取证开始后采集；不补录此前记录。 |
| 后端接口 | 记录浏览器观察到的请求 URL、方法、状态或失败信息。 |
| 接口入参 | 需主动勾选；当前采集可取得的 JSON 请求体，不保证所有请求体可用。 |
| 接口响应/错误 | 需主动勾选后采集符合限制的小型 JSON 响应；不等于服务器内部日志。 |
| 前端源码文件路径 | 不会自动扫描仓库；需要开发提供可核验的路径后补充。 |
| 后端堆栈和运行日志 | 浏览器未观察到的服务端日志需另外提供，不自动读取服务器。 |

当前最多保留 300 条取证记录；请求体会截断，响应体受格式、体积及浏览器可读性限制，不是完整抓包或 HAR 导出工具。后端日志、源码路径等补充文字可写入简单描述或材料对应的可编辑字段，并标明来源。

## 6. 一次完整使用示例

以下为演示材料，不对应已验证的真实故障，不会自动创建任何禅道记录。

**测试描述：**「在客户管理新增客户后提示保存成功，但刷新后记录消失。」

1. 截图一：保存后的成功提示，圈出提示区域。
2. 截图二：刷新后列表，圈出搜索条件和结果区域；说明使用相同筛选条件。
3. 若需请求证据，先开始取证，再复现保存与刷新操作。
4. 点击分析，回答预期问题：「保存成功后，同一筛选条件下应能查到新客户。」
5. 核对生成内容，例如：

```text
标题：客户管理—新增提示成功，刷新后记录不可见
业务路径：客户管理 → 客户列表 → 新增客户 → 保存
实际结果：保存后提示成功，刷新列表未找到该客户。
预期结果：保存成功后，在相同筛选条件下能查到新客户。
职责建议：待定位，需结合保存接口和刷新后的查询接口进一步核实。
前端事项：核对请求参数、成功提示条件、列表刷新和筛选状态。
后端事项：核对实际写入结果、事务及查询条件。
待补充：保存与查询请求、响应、测试账号权限及数据范围。
```

6. 选择真实产品、版本和主负责人，按需加协作人。
7. 只分享材料就下载 HTML；确认需要真实提单再点击创建。
8. 以返回的真实编号、链接和最终完成状态为准，不将示例编号写入交付结果。

## 7. 提单状态与恢复

| 界面状态 | 含义与处理 |
| --- | --- |
| 创建中 | 创建意图已保存，尚未完整回读；等待结果。 |
| 创建结果待核实 | 请求结果不明确，不能视为未创建；继续使用原草稿核实，必要时在禅道查材料编号。 |
| 正在上传 | Bug 已创建，正在附加图片及材料。 |
| 部分完成 | 可能已有 Bug，但附件、正文嵌图或回读核实尚未全部成功。按逐项状态处理。 |
| 已完成 | 编号、主负责人、正文及上传步骤已核实。 |

发生超时后，原按钮会变为 **「继续核实／补传」**。保留原草稿，工具会先查已有记录或续传。若仍无法确认，交给管理员使用 `reconcile` 指定核实后的真实 Bug 编号；详情见 [CLI 与恢复命令](../skills/zentao-buglens/references/commands.md)。未确认附件确实缺失前，不强制重传。

## 8. 常见问题

**安装 Skill 后还要安装 DSH 吗？**

不需要。Skill 可以调用 npm 包提供的 CLI 和工作台。DSH 插件是另一个独立入口。

**只粘贴截图，能自动得到接口和后端日志吗？**

不能。需要接口证据时，先用扩展开启取证再复现；服务器内部日志和源码需另外提供。没有证据的内容会保留为待补充。

**模型不可用或尚未配置怎么办？**

检查 `BUGLENS_CONFIG`、配置文件、Key 环境变量以及模型是否支持图片和 JSON。现有草稿及已有材料可继续查看，连接问题不会被显示为提单成功。

**最近指派列表为空怎么办？**

先选产品并同步历史，查看界面的范围和错误提示。没有本人可核验记录、无历史权限或账号不匹配都会影响结果；可手动搜索当前团队成员。

**扩展提示无法连接或令牌缺失怎么办？**

先运行 `dsh-zentao-buglens open`，使用返回的完整地址重新配对。不要只填端口地址，也不要把 `127.0.0.1` 改为局域网或公网地址。

**开始取证失败怎么办？**

确认当前是普通 HTTP/HTTPS 业务页面，浏览器允许扩展调试访问。若调试权限被其他调试器占用，先结束冲突的调试会话，再重新尝试。取证开始成功前的请求不会补录。

**提示目标 Skill 已存在怎么办？**

说明已有同名安装。安装器不会覆盖个人修改；检查现有目录，备份后再升级，或指定其他父目录。

**工作台启动失败怎么办？**

先保留工作，使用 `dsh-zentao-buglens serve` 前台诊断。默认端口为 43921，避免重复启动占用同一端口的服务；不要在原服务运行时盲目启动第二个实例。

## 9. 数据与隐私

- 默认本机数据目录为 `~/.local/share/zentao-buglens`，可用 `BUGLENS_DATA_DIR` 修改；草稿、图片、导出材料及指派记录保存在此。
- 服务日志位于该数据目录的 `service.log`；配置文件位于管理员设置的 `BUGLENS_CONFIG` 路径。
- AI 分析会把截图、选区及所选页面上下文发送至团队配置的模型网关；提交后相关材料进入禅道。
- 接口入参与 JSON 响应默认不采集，需主动开启；规则会对部分敏感文本脱敏，但不能保证覆盖所有业务敏感信息。
- 图片中的手机号、客户信息、密码等像素内容不会自动脱敏，添加前先遮挡。不要提交完整 Key、Cookie 或 Token。
- 本机工作台不是多人共享系统，不要映射到公网；每位测试同事使用自己的禅道身份。
