# 禅图 BugLens Skill 使用说明

适用 Skill：`zentao-buglens`。共用核心版本：`dsh-zentao-buglens@0.1.0`。

面向通过 AI 工具调用 Skill 的测试同事。**可以独立安装，无需先安装 DSH。**

## 1. Skill 能做什么

在支持本 Skill 的 AI 工具中，用自然语言描述问题，由 Skill 协调本机 CLI 和工作台完成：

**接收截图 → 澄清预期 → 生成故障材料 → 建议前后端排查分工 → 推荐最近指派的开发 → 按用户要求提交禅道。**

测试同事负责提供现场、回答关键问题、确认预期和选择负责人。拖图、精确红框和推荐选项主要在本机工作台完成；宿主支持交互问答时，也可在聊天中展示同组问题。

Skill 是 AI 的工作指引，npm 包提供实际执行功能的核心程序。安装 Skill 不会自动获得浏览器权限，也不会自动配置模型 Key 或登录禅道。

## 2. 安装 Skill

需要 Node.js 22.15 或以上及 npm。在终端运行：

```sh
npx --yes dsh-zentao-buglens@0.1.0 install-skill
```

默认安装到：

```text
~/.agents/skills/zentao-buglens
```

宿主使用其他目录时，指定 skills 的父目录；安装器会在其中创建 `zentao-buglens`：

```sh
npx --yes dsh-zentao-buglens@0.1.0 install-skill --target /absolute/path/to/skills
```

安装结果包含 `SKILL.md`、`agents` 和 `references`。同名目录已存在时，先检查、备份已有安装，安装器不会覆盖个人修改。宿主何时重新发现 Skill 由其机制决定。

也可从 [GitHub Release](https://github.com/zhan1024/dsh-zentao-buglens/releases/tag/v0.1.0) 下载 `zentao-buglens-skill-0.1.0.zip`，将解压后的 `zentao-buglens` 文件夹放入宿主 skills 目录。使用 ZIP 仍需本机具备运行核心 CLI 的环境。

## 3. 首次配置

请管理员先完成三项配置：

| 配置 | 用途 |
| --- | --- |
| `BUGLENS_CONFIG` 指向的团队配置文件 | 告诉核心程序如何连接模型和禅道。 |
| 支持图片输入及 JSON 输出的模型网关 | 分析截图；Key 从配置指定的环境变量读取。 |
| 本人的禅道身份及权限 | 查询团队、同步本人指派历史、创建 Bug 和上传附件。 |

禅道可复用本人在交互终端执行 `zentao login` 后的本机 Profile。不要把密码、Token 或 AI Key 发到聊天。

AI 宿主执行 CLI 时也必须能读取相关环境变量。聊天工具可用，不代表本机识图网关已经配置；Skill 不会自动继承聊天工具的模型凭据。

详细步骤见 [团队配置与禅道接入](./CONFIGURATION.md) 和 [通用使用说明的首次配置部分](./USER-GUIDE.zh-CN.md)。

## 4. 第一次怎么调用

在已经识别此 Skill、支持该调用语法的宿主中，复制下面的话：

```text
$zentao-buglens
请打开禅图 BugLens 工作台，让我粘贴页面截图并圈出问题区域。
我会补一句问题描述，请通过推荐选项帮我确认预期、复现步骤和业务路径，
生成规范 Bug 材料，并给出前后端排查建议。
这次先整理材料，不提交禅道。
```

Skill 会通过核心程序打开工作台。未全局安装 CLI 时，也可以直接运行：

```sh
npx --yes dsh-zentao-buglens@0.1.0 open
```

浏览器没有自动打开时，使用命令返回的完整本机地址。地址含 `#token=`，仅用于本机访问，不发送到公开群、仓库或 Issue。

## 5. 把截图交给 Skill 的三种方式

### 方式一：工作台粘贴

1. 打开工作台，点击 **「＋ 新建故障材料」**。
2. 粘贴、拖入或选择图片。
3. 点击缩略图，在截图上拖动鼠标画红框，填写图片说明并保存。
4. 填一句问题描述，点击 **「分析截图，生成材料」**。
5. 选择推荐答案并点击 **「应用到故障材料」**，再核对材料。

支持 PNG、JPEG、WebP；最多 8 张，每张不超过 10MB。

### 方式二：提供本机文件路径

如果 AI 宿主能读取图片文件，可以说：

```text
$zentao-buglens
请创建故障草稿，导入截图：/absolute/path/error.png。
现象：新增客户后提示保存成功，但刷新后列表找不到该客户。
先向我确认关键细节，再生成材料，不提交禅道。
```

将示例路径换成真实路径。Skill 可调用 `create`、`add-image` 和 `analyze`。聊天中的图片若不能取得可读文件，改在工作台粘贴；不能把聊天里显示了图片当成已经导入草稿。

### 方式三：配合浏览器扩展

需要当前业务页地址、可见菜单按钮、控制台错误和接口证据时，单独安装 Chrome/Edge 配套扩展，与工作台配对。

**先开始取证 → 再复现故障 → 最后截图**。此前的请求和日志无法补录。JSON 接口入参与响应需主动勾选采集，并受格式和体积限制。

完整操作见 [通用使用说明中的浏览器取证部分](./USER-GUIDE.zh-CN.md)。Skill 本身不会自动访问已登录浏览器、扫描业务仓库或读取服务器日志。

## 6. 常用调用话术

### 6.1 只生成材料，不提单

```text
$zentao-buglens
根据我的截图和描述生成故障材料，先不要提交禅道。
包含业务操作路径、复现步骤、实际结果、预期结果、
前后端排查事项、判断依据和待补充信息。
不确定的内容请问我，或标记待补充，不要编造接口和源码路径。
```

### 6.2 让测试同事选择预期

```text
$zentao-buglens
我知道这个页面表现不对，但说不清正确预期。
请结合截图提出少量关键问题和推荐答案，允许我自己填写或选择不确定。
确认后更新同一份材料。
```

实际问题来自分析结果，不保证每次都有固定问题。工作台中的答案通过 **「应用到故障材料」** 写回；确认 AI 推测的预期后，再决定是否提交。

### 6.3 推荐最近指派的同事

```text
$zentao-buglens
继续当前草稿，先确认真实产品和项目。
同步我本人最近在禅道的指派记录，展示候选同事、最近指派时间和来源，
让我选择主负责人和协作人。先不要提交。
```

默认扫描当前产品最近编号的最多 200 个可访问 Bug，查找最近 30 天的本人指派事件，需说明覆盖范围。历史不可用或账号无法唯一匹配时，改从可访问团队中选择，不把 Bug 当前处理人当成本人历史。

### 6.4 确认后创建禅道 Bug

```text
$zentao-buglens
当前材料、预期、真实产品和影响版本均已核对。
请按我已选择的主负责人和协作人创建一条禅道 Bug，
附上截图、红框标注和故障材料。
返回真实 Bug 编号、链接、负责人和各项上传核实状态。
如果超时或结果不确定，先核实原草稿，不重复建单。
```

仅在实际确认字段后使用这段话。字段缺失时先补齐。用户明确要求提交或点击 **「创建禅道 Bug」** 会执行真实写入；只要求材料分析或演示时，不创建真实 Bug。

### 6.5 只导出材料

```text
$zentao-buglens
请导出当前已确认的材料，不创建禅道 Bug。
给我带截图和红框的离线 HTML，以及 Markdown 的保存位置。
```

HTML 内嵌图片，适合整体转交同事；单独分享 Markdown 时需另带对应图片。

### 6.6 继续核实失败或超时的提单

```text
$zentao-buglens
刚才的草稿提交后显示待核实或部分完成。
请继续检查原草稿的 Bug 编号、负责人、正文和附件，
说明已完成项、缺失项和下一步。不要重新建相同 Bug。
```

## 7. 怎样确认已经完成

材料应包含页面与业务路径、复现步骤、实际与预期结果、预期依据、截图、排查职责、主负责人、协作人、待补充信息及已采集的浏览器证据。

要求真实提单时，还需核对：

- 真实 Bug 编号及可访问链接。
- 回读的主负责人符合选择。
- 正文、图片和材料附件完成上传及关联核实。
- 最终状态为 `done` / **「已完成」**。

`partial` 是部分完成，`uncertain` 是创建结果待核实，不能当作全部成功。保留原草稿核实或补传；人工恢复由管理员按 [恢复命令说明](../skills/zentao-buglens/references/commands.md) 操作。

## 8. 职责建议与使用边界

Skill 可以建议前端、后端、前后端共同或待定位，给出依据及各方排查事项。截图和 HTTP 状态不能独立证明根因。

例如「保存提示成功，但刷新后数据不可见」，可能需要前端检查请求、列表刷新和筛选条件，也可能需要后端检查写入、事务和查询。证据不足时保留待定位。

共同问题只建一条 Bug、一位主负责人，正文列协作人及分工，不自动拆成两单，也不保证禅道发出协作通知。源码路径及后端日志需要另外提供并标明来源。

## 9. 常见问题

**为什么还会打开工作台？**

工作台用于粘贴多图、精确圈选、选择推荐答案和查看提单状态。Skill 负责在 AI 工具中协调步骤，部分宿主也能通过 CLI 处理可读文件。

**推荐选项一定在聊天里弹出吗？**

不保证。当前明确提供推荐问答的是工作台，聊天中的交互取决于宿主能力。

**分析报模型错误怎么办？**

检查执行 CLI 的环境是否有 `BUGLENS_CONFIG` 和所需 Key，模型是否支持图片及 JSON。已有工作台进程可能仍使用旧配置，需管理员重启服务。

**能自动修复代码吗？**

本 Skill 用于材料分析和提单，不自动修改业务源码。开发修复是另一个需要明确授权的任务。

**截图和材料需要脱敏吗？**

需要。AI 分析会向团队模型发送截图及所选页面上下文，提单后材料进入禅道。图片像素不会自动脱敏；先遮挡敏感信息，不提供完整 Key、密码、Cookie、Token 或工作台令牌地址。
